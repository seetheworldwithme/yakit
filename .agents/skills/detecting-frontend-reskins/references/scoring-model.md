# 前端同源换皮检测：独立性评分模型

> 本文件是评分体系的**单一事实源**。改分数、阈值、子指标、动作模板前先读这里。
> 配套实现：`scripts/reskin_audit.py`（`DEFAULT_CONFIG` + `DIMENSION_META` + `ACTION_TEMPLATES`）。

## 1. 适用场景

评测**两个前端项目是否存在「简单换皮」关系**——即完全保留核心技术骨架、页面配色体系、整体页面布局逻辑，仅修改表层文案、图标等非核心元素。

典型用途：**两款同源产品参加竞标**前做自检，迭代到两款产品「看不出同源、像独立开发」，达到竞标安全线。

## 2. 评分语义（独立性得分，越高越安全）

**总分 100 = 独立性得分。**

- **100 = 完全独立**（两款产品无任何可识别同源特征）。
- **0 = 完全相同**（同一份代码）。
- **方向：分数越高越安全**；检测到同源重叠即**扣分**。

```
维度独立分 = 维度满分 ×（1 − 维度重叠度）
总分       = Σ 四维度独立分
维度重叠度 = 该维度下各子指标重叠度的「份额加权平均」
```

## 3. 四维度权重（满分，和 = 100）

| 维度 | 满分 | 检测方向 |
| --- | ---: | --- |
| 技术骨架 skeleton | 25 | 项目目录结构、技术栈选型、工程配置、核心工具链复用 |
| 页面布局 layout | 30 | 页面路由结构、组件层级关系、页面元素排版逻辑 |
| 视觉体系 visual | 25 | 色彩系统、字体规范、图标库、通用组件样式 |
| 业务逻辑 logic | 20 | 核心业务流程、状态管理逻辑、接口调用逻辑 |

> 权重依据：用户「换皮」定义强调「骨架 + 配色 + 布局」三者被保留 → 三者权重高；页面布局是最直观的同源信号 → 最高；业务逻辑在「功能保留」场景下重叠可预期 → 最低。

## 4. 三档阈值（竞标安全线 ≥70）

| 独立性得分 | 等级 | 含义 | 行动 |
| ---: | --- | --- | --- |
| **≥70** | ✅ 完全独立项目 | 常规代码审计也判为独立，**竞标安全区** | 达标，维持 |
| 40–69 | ⚠️ 存在部分复用痕迹 | 有同源线索 | 继续迭代高危维度 |
| **≤39** | ❌ 高度疑似换皮 | 同源可识别，**禁止竞标** | 必须整改 |

## 5. 身份 override（同源铁证，最致命信号）

若以下**任一**命中（非空且相等），总分**钳制上限为 39**（强制「高度疑似换皮」）：

- **git origin 相同**（同一远端仓库）。
- **package name 相同 且 package 主版本相同**。

> 理由：这两类信号竞标方一眼可见，无法用代码改造解释为巧合。必须**首先**改造——改包名 / 切换 git 远端 / 拆分仓库——否则代码层迭代再低也过不了审计。

仅 package name 相同但主版本不同时，作证据展示但**不**钳制（可能是巧合重名）。

## 6. 子指标扣分细则

每个子指标：`子指标总分 = 维度满分 × 份额 / Σ维度内份额`；`扣分 = 子指标总分 × 重叠度`。

### 6.1 技术骨架（满分 25）

| 子指标 | 份额 | 子指标总分 | 检测内容 |
| --- | ---: | ---: | --- |
| 依赖版本重叠 | 20 | 5.0 | package.json 依赖名+版本（exact/major/name 三档加权） |
| 框架/构建重叠 | 15 | 3.75 | React/Vue/Svelte/Angular/Vite/Webpack/Tailwind/antd/MUI 集合 Jaccard |
| 目录结构重叠 | 20 | 5.0 | 目录路径签名（前 4 级 + `dir/*ext`）集合 Jaccard |
| 路由/配置重叠 | 20 | 5.0 | 路由 path 字符串加权 Jaccard |
| 状态管理重叠 | 15 | 3.75 | redux/zustand/mobx/pinia/vuex/jotai 等集合 Jaccard |
| 工程配置相似度 | 10 | 2.5 | 重要配置文件（vite/webpack/tsconfig/eslint/prettier…）逐文件 SequenceMatcher |

### 6.2 页面布局（满分 30）

| 子指标 | 份额 | 子指标总分 | 检测内容 |
| --- | ---: | ---: | --- |
| 组件层级/标签序列重叠 | 30 | 9.0 | JSX/Vue/Svelte/HTML 标签序列（每文件前 500 标签）**按文件可见度加权**的最佳匹配平均 |
| 页面分区/class 命名重叠 | 20 | 6.0 | className + CSS 选择器加权 Jaccard |
| 共享组件实现重叠 | 25 | 7.5 | `components/` 下文件「字符串/数字归一化后」指纹**按可见度加权**碰撞率 |
| 响应式/断点逻辑重叠 | 15 | 4.5 | `@media` / `useMediaQuery` / `sm:` 等断点模式加权 Jaccard |
| 布局工具模式重叠 | 10 | 3.0 | 样式 token 词频加权 Jaccard |

> **可见度加权（visibility weight）**：竞标方看的是渲染出来的页面骨架，而非逐个 diff 工具文件。故布局类子指标按文件角色加权后再聚合：
> - **3.0（可见骨架）**：路径含 `pages/page/layout/routes/shell`，或入口类文件名（`App/Layout/Shell/Workspace/MainOperator/index`）。
> - **0.3（管线代码）**：路径含 `utils/hooks/store/services/lib/constants/enums/types/models/api` —— 不渲染页面，稀释作用被压低。
> - **1.0（普通组件）**：其余。
>
> 这样做两点改善：① 长尾工具文件不再稀释「页面骨架相似度」信号；② 指标随增量改造**线性下降**（旧版 top-K 均值在剩余匹配文件 ≥K 时一直显示 100%，掩盖进度）。


### 6.3 视觉体系（满分 25）

| 子指标 | 份额 | 子指标总分 | 检测内容 |
| --- | ---: | ---: | --- |
| 配色系统重叠 | 30 | 7.5 | `#hex` / `rgba` / `hsla` / `var(--*color*)` 加权 Jaccard |
| 字体比例重叠 | 25 | 6.25 | font-size/line-height/font-weight/font-family 规则加权 Jaccard |
| 间距比例重叠 | 20 | 5.0 | margin/padding/gap 规则加权 Jaccard |
| 动效规则重叠 | 15 | 3.75 | transition/animation/@keyframes 规则加权 Jaccard |
| 设计 token 命名重叠 | 10 | 2.5 | CSS 变量名（`--*`）加权 Jaccard |

### 6.4 业务逻辑（满分 20）

| 子指标 | 份额 | 子指标总分 | 检测内容 |
| --- | ---: | ---: | --- |
| 业务逻辑 token 重叠 | 35 | 7.0 | 代码 token 词频加权 Jaccard |
| 第三方服务配置重叠 | 25 | 5.0 | Sentry/Firebase/Stripe/axios/fetch/GraphQL 等服务名加权 Jaccard |
| API 端点/集成重叠 | 20 | 4.0 | URL/endpoint 字符串加权 Jaccard |
| 工具函数指纹重叠 | 20 | 4.0 | function/const 声明名加权 Jaccard |

## 7. 高危信号（单维度触发即风险升级，独立于总分）

- 技术骨架重叠 **> 70%**（目录/依赖/构建几乎完全复用）。
- 页面组件层级重叠 **> 65%**（页面组装方式未重建）。
- 业务逻辑 token 重叠 **> 60% 且**技术骨架重叠 **> 60%**（功能性同源）。

## 8. 针对性修改建议（按「可回收分」降序）

对每个**重叠度 > 30%** 的子指标生成一条建议。可回收分定义：

```
可回收分 = 子指标总分 × max(0, 当前重叠度 − 15%)
```

> 15% = 「完全独立项目」档的典型残留重叠（同框架/语言的基础 token 噪声）。把该子指标从当前重叠压到 15%，能恢复的独立性分数即「可回收分」。

优先级按可回收分分档：**P0 ≥5 / P1 ≥3 / P2 ≥1.5 / P3 ≥0.5 / P4 其它**。

每条建议含：优先级 / 维度 / 子指标 / 当前重叠 / 已扣分 / **预期回收分** / **具体动作**（见 `ACTION_TEMPLATES`，每个子指标一种可落地动作）。

### 迭代路径

报告末尾输出：
- 当前独立性 → 距 ≥70 安全线差值。
- 最大可回收（所有 >15% 子指标全压到 15%）。
- 可行性：最大可回收 ≥ 差值则「可行」，否则须先消除身份 override。
- Top 5 改动（累计可回收）。

## 9. 重叠度计算原语

| 原语 | 用途 |
| --- | --- |
| `weighted_jaccard(counter_a, counter_b)` | 带 frequency 的 Jaccard，用于词频/计数类信号（颜色、token、路由…） |
| `jaccard(set_a, set_b)` | 普通集合 Jaccard，用于框架/状态库/目录签名 |
| `sequence_similarity(seq_a, seq_b)` | SequenceMatcher.ratio()，用于标签序列、配置文件正文 |
| `compare_dependency_versions` | exact=1.0 / major=0.75 / name=0.45，归一化到 max(len) |

## 10. 证据标准

- **跨维度交叉验证**：架构 + 布局 + 视觉 + 逻辑多维度同时高分，比单维度高分更强。
- **文件可追溯**：证据含路径、依赖名、路由、选择器、端点、函数名、包身份、git 身份。
- **归一化**：忽略 `node_modules` / `dist` / `build` / `.git` 等生成物；lockfile 噪声不计入依赖身份。
- **可解释**：每个扣分都落到命名子指标 + 证据抽样。

## 11. 调参（`--config config.json`）

```json
{
  "weights": {"skeleton": 25, "layout": 30, "visual": 25, "logic": 20},
  "tiers": {"independent_min": 70, "partial_min": 40, "identity_cap": 39},
  "high_risk_overlap_signals": {"skeleton_core": 70, "layout_structure": 65},
  "remediation": {"target_overlap": 0.15, "submetric_trigger": 0.30, "priority_thresholds": [5.0, 3.0, 1.5, 0.5]},
  "identity_override": {"same_git_origin": true, "same_package_name_and_major": true}
}
```

约束：权重 key 必须是 `skeleton/layout/visual/logic`，且和 = 100。改阈值/权重后，分数不再适用默认标准，需在报告中声明。
