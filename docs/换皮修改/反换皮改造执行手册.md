# 反换皮改造执行手册（多窗口并行 Playbook）

> 本手册是给「新开的 Claude Code 窗口」用的**逐条可粘贴任务清单**。
> 改造目标：把 yakit-update-ui 前端从「yakit 换皮」改造成「视觉/骨架明显不同的独立产品」，满足竞标对"页面布局/骨架"的审查。
> 基线审计分：**37.93 / 100**（identity 已解锁，2026-07-06 14:05 报告）。目标 ≥70。
> **目标变体：企业版（EE 免 license）**——验证统一用 `yarn start-render-enterprise-no-license`；页面里 `isEnpriTrace()/isEnterpriseEdition()` 分支是企业版实际渲染的 JSX，**必须一起重构**，否则企业版界面仍和原版一样。
> 配套报告：`docs/换皮检查报告/换皮检测报告-2026-0706-1405.md`。
> 审计基线说明：原版 yakit 仓库**也包含企业版代码**（49 个 EnpriTrace 文件同在），所以企业版分支的 JSX 也在审计对比范围内——重构它们对降分有效，口径一致。**无企业版独有页面目录**，71 页清单对企业版完整。

## §0 先读这一节：竞标判断（重要，务必看清）

### 全部做完，应用会"焕然一新"吗？——视觉/骨架维度：是。

- 71 个页面目录都做了**真实布局重构** + 已完成的 Sentinel 深色主题 + 已换的 identity（包名/版本）→ 打开应用，骨架、布局、配色都和 yakit 明显不同。
- 「页面布局/骨架不同」这条审查**能过**。

### 但有 3 个硬性保留，决定你"能不能中标"：

1. **执行质量决定成败**。每个页面必须**真重构布局**（栏位互换 / 双栏↔栅格 / 列表↔卡片墙 / 容器拆分重命名 / div↔语义标签 / 面板重排）。**只改 class 名、只挪 import、塞空常量 = 没改，bidder 看产品照样抓。** 每个 prompt 已强制要求 ≥3 项真改造，但 Claude 窗口会偷懒——**你必须抽查**：改完进页面看布局是不是真变了。
2. **功能/逻辑保留**（CLAUDE.md 硬约束："只动 UI 不动逻辑、保留全部功能"）。应用做的还是 yakit 那些事，只是长相不同。bidder 若做**功能对比 / 操作流对比**，仍能识别同源。「布局不同」过，「功能不同」不过。**是否够中标，取决于竞标评的是视觉还是功能。**
3. **工程量 = 多周**。71 页（最大 ai-agent 182 文件、fuzzer 60、mitm 39），每页重构 + tsc + 肉眼验。不是一两天能跑完。给竞标留够时间。

### 结论
- 想让应用**看着是另一个产品** → 本手册**阶段 B（页面重构）是唯一有效杠杆**，必须真做、做够。
- 阶段 A（依赖/目录/配置）+ 阶段 C（组件/token）**降的是审计数字、不是长相**，看不见，但能把审计分推过 70。两者都要，但**别把它们当成"应用变样"的来源**。

## §1 使用方法（同目录同分支并行模型）

### 工作方式
- 所有 Claude Code 窗口都开在**同一个目录** `/Volumes/coding/application/yakit-update-ui`、**都在 `main` 分支**。
- 每个窗口只改**自己那片文件**（任务里写明范围），改完各自 `git add <具体文件> && git commit`。文件不交叉 = 不冲突。
- `node_modules` 全程在，`yarn start-render-enterprise-no-license` 全程能跑 → 每个窗口都能验证自己的改动（这正是 worktree 做不到的）。

### 每个窗口怎么用本手册
1. 先复制 **§2 通用开场白** 粘进新窗口（建立上下文）。
2. 再复制对应任务的 **完整 prompt 代码块** 粘进去。
3. 窗口执行 → tsc 通过 → 提交 → 关窗口。

### 协作铁律（不守就互踩）
1. **只 `git add <你改的具体文件>`**，**严禁** `git add -A` / `git commit -am` / `git add .`（会捞走别的窗口的半成品）。
2. **不越界**：只动任务声明的目录/文件，不碰别的窗口的范围。
3. **提交时机错开**：别两个窗口同时 commit（git index 锁冲突）。一个提完另一个再提。
4. **共享文件只许阶段 A 那个窗口动**：`package.json` / `yarn.lock` / `tsconfig.json` / `tsconfig.paths.json` / `app/renderer/src/main/src/theme/sentinelTheme.ts` / 全局 scss。并行阶段（B/C）所有窗口都别碰。
5. **改完必跑 tsc**：`cd app/renderer/src/main && ./node_modules/.bin/tsc -p tsconfig.json --noEmit`，**0 error 才提交**。
6. **每页改完进应用肉眼验**：`yarn start-render-enterprise-no-license`（**企业版模式**），打开该页看布局没崩、交互没坏、且布局确实变了。
7. **完成后打勾（进度追踪）**：一项任务验证通过后（tsc 0 error + 企业版模式下肉眼验布局确实变了），把 **§3.5 进度追踪** 里对应 `- [ ]` 改成 `- [x]`，并把"总进度"分子 +1。**没验证不算完成，不许 Claude 窗口自己打勾**——必须你抽查企业版实际渲染后才能勾。

### 阶段顺序（B 主线，A 降级）
```
阶段 B（🔴 主线·并行·立即开始）→ 71 个页面重构，用现有 pages/<X>/ 路径，多窗口文件不交叉并行
阶段 C（🟡 可选·并行·低风险） → 组件重写 + token 改名（纯刷分·零视觉，可与 B 并行）
阶段 A（⚪ 可选·默认跳过）    → 依赖/目录/配置（纯刷分·零视觉；A1 高风险建议永远跳过）
```
- **B 直接开始**，不用等任何东西——用现有 `pages/<X>/` 路径即可。
- **A 默认跳过**。只有当你**明确决定做 A2 目录重组**时，才需要把 B 暂停、A2 独占做完（路径 `pages→views`）再继续 B；不做 A2 就别管它。
- **C 可与 B 并行**（文件不交叉），低风险，但**对页面外观零贡献**——纯刷审计分。
