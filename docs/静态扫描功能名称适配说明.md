| 项目   | 内容                                  |

## 一、背景与目标

产品界面重塑为「智能化代码安全检测与验证系统」后，界面功能名称仍沿用「代码审计」「数据库」等旧命名，与静态代码扫描产品主线及任务书验收名称存在脱节。本次适配的三个目标：

1. **原型名称上首页**：任务书及第三方测试报告的验收名称「智能化代码安全检测与验证原型」，须在首页首屏显眼、完整展示（可截图、可验收）；
2. **菜单贴近主线**：顶部菜单与页签改为贴近静态代码扫描业务的短功能名，并在菜单、页签、首页卡片、快捷入口、页面标题中统一使用；
3. **命名不夸大能力**：任务书中的研究方法名与验收指标，仅在具备实现证据或实测数据后展示，避免「文案先行」带来验收风险。

适配范围仅限界面可见名称与首页布局，不涉及代码级重命名与引擎功能改动，不影响其它产品版本。

---

## 二、命名原则：三层名称，各就其位

| 层级    | 名称                 | 使用位置           | 处理   |
| ----- | ------------------ | -------------- | ---- |
| 产品名   | 智能化代码安全检测与验证**系统** | 窗口标题、启动页、应用元信息 | 保持不变 |
| 验收原型名 | 智能化代码安全检测与验证**原型** | 首页首屏主标题        | 新增展示 |
| 用户功能名 | 短、可操作的菜单名（2–8 个汉字） | 菜单、页签、功能卡、快捷入口 | 统一修订 |

配套约束：

- 任务书中的研究方法名（如「结构化提示模板驱动大模型推理」）不直接用作菜单名，放至对应页面的能力说明区；
- 指标类文案（百万行代码 ≤5 分钟、准确率 ≥90%、自动化利用成功率 ≥85%）属于**验收目标**，须有实测数据支撑后才能作为当前成绩展示；
- 同一功能在全产品使用同一套短名，避免一词多名。

## 三、命名对照方案

### 3.1 顶部菜单与页签（10 项）

| 序号  | 现名        | 调整为        | 定位说明                               |
| --- | --------- | ---------- | ---------------------------------- |
| —   | 一级菜单：代码审计 | **静态代码扫描** | 产品主流程入口                            |
| 1   | 项目管理      | **扫描项目**   | Java / JavaScript / PHP 项目的输入与编译管理 |
| 2   | 代码审计      | **静态分析**   | 菜单/页签空间有限用短名；页面标题与首页卡片用「静态分析工作台」全称 |
| 3   | AI代码审计    | **智能辅助审计** | 大模型辅助推理；完整方法名放页面说明区                |
| 4   | 代码扫描      | **扫描任务**   | 规则选择、扫描执行、任务与结果查看                  |
| 5   | 规则管理      | **检测规则**   | 当前实际管理 SyntaxFlow 检测规则，不宣称为「漏洞特征库」 |
| 6   | 审计漏洞      | **漏洞结果**   | 扫描/审计发现结果的统计、定位与详情                 |
| 7   | Java 反编译  | 保留         | Java 输入的辅助处理能力，不强行映射为独立研究方法        |
| —   | 一级菜单：数据库  | **报告中心**   | 该分组下仅「报告」一项，原名无法表达用户任务             |
| 8   | 报告        | **检测报告**   | 原型验证、扫描结果交付的报告入口                   |

### 3.2 首页首屏（原型名展示位）

| 位置       | 现值                       | 调整为                              |
| -------- | ------------------------ | -------------------------------- |
| 首页主标题    | 代码审计工作台                  | **智能化代码安全检测与验证原型**（完整展示、不缩写）     |
| 副标题      | 区分 AI 联网审计与 SSA 离线规则审计…… | **面向电力业务程序的静态代码扫描、漏洞定位与智能辅助验证**  |
| 课题标签（新增） | 无                        | **课题：电力业务程序语义重构与静态符号验证协同漏洞挖掘技术** |

同步为标题区增加窄窗口换行策略，保证常用窗口宽度下主标题完整、统计卡不重叠不截断。

### 3.3 首页功能卡（调序 + 主次调整）

| 顺序  | 现卡片           | 调整为                   | 说明                       | 视觉层级    |
| --- | ------------- | --------------------- | ------------------------ | ------- |
| 1   | 传统代码审计        | **静态分析工作台**           | 基于检测规则分析项目代码，查看调用关系与风险位置 | 主卡（深绿）  |
| 2   | 代码扫描          | **扫描任务**              | 按规则组或关键词执行批量扫描并查看结果      | 主卡（深绿）  |
| 3   | AI 代码审计       | **智能辅助审计**            | 对复杂业务逻辑、跨文件关联和风险原因进行辅助研判 | 辅助卡（浅色） |
| 4   | AI Skill 安全分析 | **AI Skill 安全分析**（保留） | 真实能力名称，作为扩展能力展示          | 辅助卡（浅色） |

调整逻辑：体现「静态扫描为主、AI 为辅」的产品定位。原布局中两张 AI 卡为主卡、静态能力为次卡，与定位相反，故顺序与视觉主次**同步调整**，而非仅换文字。

## 四、任务书能力名称的落位

任务书中的方法与能力名称按「证据充分度」分三类处理，防止界面展示超出已验证能力：

| 类别                           | 名称                        | 落位                                 |
| ---------------------------- | ------------------------- | ---------------------------------- |
| **① 直接展示**（前端已有实现证据）         | 智能化代码安全检测与验证原型            | 首页主标题                              |
|                              | 电力业务程序语义重构与静态符号验证协同漏洞挖掘技术 | 首页课题标签、关于/版本信息页                    |
|                              | 静态分析引擎                    | 「静态分析工作台」页面说明区（前端已有 SSA 编译与规则审计链路） |
| **② 待确认后展示**（需引擎/算法负责人确认口径）  | 上下文敏感信息识别                 | 静态分析工作台能力标签                        |
|                              | SSA IR 语法树映射、静态单变量赋值分析    | 项目编译/静态分析说明                        |
|                              | 跨语言语法树映射规则集（Java/JS/PHP）  | 检测规则页支持能力说明                        |
|                              | 结构化提示模板驱动大模型推理            | 智能辅助审计页面说明                         |
| **③ 暂不展示**（前端未见实现证据，展示即构成夸大） | 「漏洞特征-攻击模式-环境约束」三元组表征     | 不展示，待功能落地后另行验收                     |
|                              | 代码语义相似度评估与路径可达性验证         | 不展示，同上                             |
|                              | 漏洞利用代码生成（研究内容 3）          | 不通过改名纳入现有菜单；如后续确有功能，单独建流程并验收       |

语言支持口径：Java、JavaScript、PHP 需在「项目创建 → 编译 → 规则选择 → 扫描 → 结果查看」全流程实测通过后，方可作为「已支持」对外展示。

## 五、关键裁定说明（与初版建议的差异）

初版建议经逐项审校后，以下调整需重点说明：

| 初版建议                  | 裁定       | 理由                                                 |
| --------------------- | -------- | -------------------------------------------------- |
| 产品名全局由「系统」改「原型」       | **不采用**  | 产品名已用于窗口标题、启动页与应用元信息，全局更换影响面大；原型名在首页首屏精确展示即可满足验收要求 |
| 代码审计 → 静态分析引擎         | **调整**   | 「引擎」是能力名不是任务名；菜单用「静态分析」，页面标题与首页卡片用「静态分析工作台」        |
| AI代码审计 → 大模型推理审计      | **调整**   | 改「智能辅助审计」；「结构化提示模板驱动大模型推理」的完整实现待后端确认后再写入能力说明       |
| 代码扫描 → 全链路漏洞挖掘        | **不采用**  | 全链路覆盖编译、分析、验证多个环节，超出单个页面职责；改「扫描任务」                 |
| 规则管理 → 漏洞特征库          | **暂不采用** | 当前管理的是 SyntaxFlow 检测规则；形式化漏洞特征模型确认后方可升级此名，先改「检测规则」 |
| AI Skill → 领域知识增强安全分析 | **不采用**  | 与后端实际能力（ai_skill_audit 模式）并非同一功能，直接改名构成功能错配        |
| 长方法名直接作首页卡片标题         | **不采用**  | 卡片空间有限（18px 标题 + 44px 图标 + 徽标同排），长名一律放说明区          |
