# XLSX 转 SQLite（通用精简版）

## 目标
将 xlsx 文件内容写入 SQLite，且保证导入结果与源文件一致。

这个 skill 是通用工具，不做业务识别，不做字段映射，不依赖任何特定列名。

## 适用场景
- 用户只需要把 xlsx 转成可查询的 SQLite 数据库
- 用户要求“原样导入”
- 用户要求可验证的一致性（不是“尽量一致”）

## 输入与输出
- 输入：一个 xlsx 文件，或包含多个 xlsx 文件的目录
- 输出：一个 `.db` 文件，每个工作表对应一张表
- 表名规则：`文件名__工作表名`（自动清洗为 SQLite 安全标识符，冲突时自动加后缀）

## 核心原则
1. 不识别数据类型
2. 不重命名业务字段
3. 不做金额/日期/证件号等“智能清洗”
4. 不丢列、不调列序
5. 不按业务规则去重

## 一致性定义
一致性按以下规则校验（全部通过才算成功）：

1. 列名一致
- Excel 首行作为列名
- 空列名自动补成 `col_序号`
- 重名列自动补后缀 `_2/_3...`

2. 列顺序一致
- SQLite 建表列顺序与 Excel 列顺序完全一致

3. 行数一致
- 导入后 SQLite 行数必须等于源工作表数据行数（不含首行表头）

4. 单元格文本值一致
- 所有值按统一文本规则写入 SQLite（TEXT）
- 导入前后分别计算行级哈希并比对，确保值序列一致

## 执行流程
1. 扫描输入路径下所有 `.xlsx` 文件
2. 逐文件、逐工作表读取数据
3. 按“列名与列顺序原样保留”建表
4. 全量写入 SQLite（全部列使用 TEXT）
5. 对每张表执行一致性校验
6. 输出导入摘要（文件名、工作表名、表名、行数、校验结果）

## 依赖约束
- 必需：`sqlite3`（内置）、`openpyxl`
- 可选：无
- 不引入业务相关三方库

## 失败处理
- 单个工作表失败：记录失败原因，继续处理其他工作表
- 全部失败：明确返回失败，不输出“成功”结论

##  中文兼容（强制）

为避免中文文件名、中文工作表名、中文列名导致的异常，执行时必须遵守：

1. **全链路 UTF-8**：代码文件与输出文件统一 UTF-8 编码
2. **路径统一使用 `pathlib.Path`**：不要手工对中文路径做 `.encode()` / `.decode()`
3. **SQLite 标识符必须转义**：表名/列名使用双引号转义（如 `"纳税人识别号"`）
4. **参数绑定只绑定值，不绑定标识符**：
   - 正确：`WHERE "纳税人识别号" = :tpid`
   - 错误：`SELECT * FROM :table` 或 `ORDER BY :column`
5. **动态列名/表名必须走白名单 + 转义函数**：禁止将外部输入直接拼接为 SQL 标识符
6. **日志乱码不等于数据乱码**：若终端显示异常，优先检查 stdout 编码配置，不要直接判定导入失败
